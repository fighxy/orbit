# Протокол почтового ящика `orbit/mailbox/1`

Статус: реализован (`crates/orbit-protocol`, `crates/orbit-transport`,
`services/orbit-node`). Сквозное шифрование конвертов — отдельный следующий слой.

## Назначение

Store-and-forward: отправитель оставляет конверт на узле, получатель забирает его,
когда появится в сети, и подтверждает получение после надёжного сохранения у себя.
Подтверждение сохранения на узле не означает доставку адресату.

## Транспорт

- QUIC + TLS 1.3 через Iroh, ALPN `orbit/mailbox/1`.
- Узел адресуется строкой `<endpoint-id hex>@<ip:port>[,<ip:port>]`. Endpoint ID —
  публичный ключ узла: TLS-рукопожатие проверяет, что клиент попал именно на этот узел.
- Сторонние relay-серверы и DNS-обнаружение не используются.
- Один запрос — один двунаправленный поток: клиент пишет закодированный `Request`
  и закрывает отправку, узел отвечает одним `Response`. Кодирование — postcard;
  лишние байты после сообщения считаются ошибкой.

## Сущности

| Сущность | Что это |
|---|---|
| Mailbox ID | Публичный Ed25519-ключ владельца ящика |
| Deposit token | Случайный 32-байтовый секрет; владелец раздаёт его отправителям, узел хранит только BLAKE3-хеш |
| Item ID | BLAKE3 содержимого конверта; повторная отправка того же конверта не создаёт дубль |
| seq | Монотонная позиция элемента в ящике на этом узле |

## Аутентификация владельца

1. `Challenge` → узел выдаёт одноразовый 32-байтовый nonce, привязанный к соединению.
2. `Authenticate { mailbox, signature, registration_code? }`, где подпись Ed25519 над
   `"orbit/mailbox/auth/v1\0" ‖ node_id ‖ client_transport_id ‖ mailbox ‖ nonce`.
   Подпись бесполезна на другом узле, в другом соединении и повторно.
3. Nonce расходуется любой попыткой, успешной или нет.
4. Первая аутентификация создаёт ящик. Если в конфигурации узла задан
   `registration_code`, для создания нужен этот код.

## Запросы

| Запрос | Кто | Результат |
|---|---|---|
| `Challenge` | любой | `Challenge { nonce }` |
| `Authenticate` | владелец | `Authenticated { created }` |
| `AddDepositToken { token_hash }` / `RemoveDepositToken` | владелец | `Ok` |
| `Deposit { mailbox, token, envelope }` | отправитель с токеном | `Deposited { id, duplicate, expires_at_ms }` |
| `Fetch { after_seq, limit ≤ 100 }` | владелец | `Items { items, more }` |
| `Ack { ids ≤ 500 }` | владелец | `Acked { removed }` |
| `Status` | владелец | использование и лимиты ящика |

Ошибки: `BadRequest`, `Unauthenticated`, `Forbidden`, `NotFound`, `QuotaExceeded`,
`TooLarge`, `RateLimited`, `Internal`. Отправитель не различает «ящика нет» и
«токен неверный» — оба случая дают `Forbidden`.

## Лимиты (по умолчанию, настраиваются на узле)

| Параметр | Значение |
|---|---|
| Размер конверта | 64 КиБ (жёсткий лимит протокола) |
| Срок хранения | 14 дней |
| Элементов в ящике | 10 000 |
| Байт в ящике | 64 МиБ |
| Ящиков на узле | 1 000 |
| Токенов на ящик | 256 |
| Запросов на соединение | 600 в минуту |
| Одновременных соединений | 1 000 |

## Что раскрывается узлу

Идентификатор ящика, IP-адреса и время запросов, размеры и число конвертов,
хеши токенов. Содержимое должно приходить зашифрованным для получателя; это
обеспечивает клиентский слой E2EE, который ещё не реализован.

## Ещё не реализовано

- Сквозное шифрование конвертов и формат `orbit/1` envelope внутри них.
- Интеграция с outbox/доставкой в `orbit-core`, статусы «сохранено на узле»/«доставлено».
- Push-уведомления и relay для прямых P2P-сессий.
- Несколько узлов, репликация ящика, перенос ящика между узлами.
