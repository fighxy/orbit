# Развёртывание orbit-node

Узел хранит зашифрованные конверты для получателей, которые офлайн
(почтовый ящик). Для небольшой сети достаточно одного VPS.

## Требования

- Публичный IP и открытый **UDP**-порт (по умолчанию 7443).
- Ориентир для десятков—сотен пользователей с текстом: 1 vCPU, 1–2 ГБ RAM,
  20 ГБ диска. Это оценка, а не результат нагрузочного теста.

## Настройка

1. `orbit-node init > orbit-node.toml` — пример конфигурации.
2. Укажите `data_dir`, `public_addrs = ["<IP VPS>:7443"]` и обязательно
   `registration_code` (длинная случайная строка): без него любой, кто достучится
   до узла, сможет создать ящик.
3. Запустите через systemd (`orbit-node.service`) или Docker (`Dockerfile`).
4. При старте узел печатает `node address: <id>@<ip:port>` — эту строку
   получают клиенты. Ключ узла лежит в `data_dir/node.key`; потеря ключа меняет
   адрес узла, поэтому включите `data_dir` в резервное копирование.

## Проверка консольной утилитой

```sh
orbit-cli keygen alice.key
orbit-cli register --node <адрес> --key alice.key --code <registration_code>
orbit-cli token-create --node <адрес> --key alice.key     # токен для отправителя
orbit-cli send --node <адрес> --to <mailbox alice> --token <токен> --text "тест"
orbit-cli fetch --node <адрес> --key alice.key --ack
```

`orbit-cli` отправляет данные **без сквозного шифрования** — только для тестов.

## Что видит оператор узла

Приложения шифруют личные сообщения до отправки (HPKE); консольная тестовая утилита
по-прежнему шлёт открытый текст. Независимо от этого узел видит IP-адреса
клиентов, время и размер запросов, идентификаторы ящиков и число сообщений.
