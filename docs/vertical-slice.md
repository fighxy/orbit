# Вертикальный срез: регистрация, контакты и личные сообщения

Ветка: `feat/vertical-chat`, база PR: `feat/stage-0-rust-core-kmp`.
Один аккаунт/устройство на профиль; одна и та же Compose-форма на Windows,
Android и iOS. Узел — отдельный `orbit-node`, встроенного режима узла нет.

## Запуск узла

```sh
cargo build -p orbit-node --locked
target/debug/orbit-node init > orbit-node.toml
target/debug/orbit-node run --config orbit-node.toml
```

В конфигурации задайте каталог данных, `listen`, `public_addrs` и код регистрации
(см. [развёртывание](../deploy/orbit-node/README.md)). В одной LAN используйте
доступный телефонам IP компьютера; `127.0.0.1` относится к самому устройству.
Для внешней сети нужен доступный UDP-порт узла. При запуске узел печатает строку
`node address: <ключ>@<IP>:<порт>`, которую нужно передать клиентам. Адрес содержит
ключ узла; клиент проверяет его при QUIC/TLS-подключении.

## Пройти срез на устройствах

1. На Windows, Android и iOS создайте разные аккаунты: имя и необязательный
   код-пароль. Ключи остаются в системном secure store.
2. Откройте **«Контакты и подключение»**, вставьте адрес узла и код регистрации.
   Нажмите **«Зарегистрироваться / подключиться»**, дождитесь «Подключено».
3. На первом устройстве создайте приглашение. Выделите и скопируйте ссылку
   `orbit://invite/…`, передайте её второму устройству через знакомый канал.
4. На втором вставьте ссылку, нажмите **«Проверить приглашение»**. Сверьте полный
   ключ аккаунта с первым устройством, затем нажмите **«Добавить контакт»**.
   Подписанный ответ автоматически добавит второй аккаунт у автора приглашения.
5. Отправьте текст в обе стороны. Входящие находятся слева, свои — справа.
   «В очереди» означает локальную запись; «На узле» — запись у сервера;
   «Доставлено» — проверенную квитанцию о сохранении у адресата, не прочтение.
6. Закройте получателя, отправьте ещё один текст. Откройте получателя повторно:
   текст появляется один раз, отправитель получает «Доставлено».
7. Повторите пары Windows↔Android, Android↔iOS, iOS↔Windows. Проверьте перезапуск
   обоих приложений и временную потерю сети. После восстановления queued-текст
   должен уйти без повторного формирования конверта и без дубля в истории.

Для двух desktop-профилей используйте `ORBIT_PROFILE=alice` и
`ORBIT_PROFILE=bob`: отдельные каталоги, secure-store записи и аккаунты.

## Проверки кода

```sh
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
./gradlew :shared:jvmTest :client:jvmTest
./gradlew :apps:android:assembleDebug
```

`services/orbit-node/tests/vertical_chat.rs` использует настоящий QUIC-узел
и два application engine: регистрация, приглашение, ранний queued-текст,
взаимный контакт, доставка в обе стороны, офлайн-получатель и перезапуск,
быстрый close при активном long-poll. Storage-тест проверяет byte-for-byte
сохранение outbox, dedup, квитанцию и rollback при ошибке записи очереди.
Платформенные сборки и тесты запускает CI. Эти проверки не заменяют пунктов
выше на реальных устройствах; результаты нужно фиксировать отдельно.

## Границы

- HPKE + Ed25519 — временная схема без forward secrecy; MLS/ratchet ещё нет.
- Один контакт соответствует одному устройству. Перенос аккаунта и multidevice
  не реализованы; не копируйте профиль между устройствами.
- Приглашение действует 7 дней и даёт право обменяться контактами. Передавайте
  его только тем, кого хотите добавить. Отзыв и отдельные токены на контакт
  пока не реализованы.
- Узел хранит ciphertext до ACK/TTL; оператор видит IP, размеры, время и mailbox.
- Повреждённые/неавторизованные входящие фиксируются и удаляются из mailbox;
  ошибка локального storage оставляет сообщение на узле без ACK.
- Пушей и гарантированной доставки при закрытом/усыплённом телефоне нет.
  Откройте приложение для восстановления соединения и получения сообщений.
- Нет групп, вложений, голосовых комнат, видео и embedded node в клиентах.
